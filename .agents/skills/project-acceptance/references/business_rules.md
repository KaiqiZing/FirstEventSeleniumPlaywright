# 当前项目核心业务口径与异常流转规则

> 本文档属于 **可变配置层（`references/`）**。迁移至新项目时，将本文替换为新项目的业务口径与异常码字典，无需修改 `scripts/` 下的任何代码。

---

## 一、断言源可信分级（从高到低）

页面 DOM 上能直接看到的文案属于「前端自证」，在关键资金与安全场景下**不得作为唯一断言源**：

1. **脚本独立复算 / 落盘数据库直读（最高可信）**
   - `I-18` 结算数据：`SqliteSource` 只读直连 `settlement.db`（路径由 `/api/dbconsistency/db/meta` 动态返回）；
   - `E-03` 密文存储：只读直连 `crypto_vault.db`（路径由 `/api/crypto/vault/db/meta` 动态返回）；
   - `E-01` 口令摘要：脚本用 `hashlib.sha256(plain).hexdigest()[:16].upper()` 独立复算。
2. **浏览器真实网络栈（次高可信）**
   - Playwright 原生 `page.on("response")` 抓取真实请求体/响应体（`util/network_recorder.py`），跨 Chromium / Firefox / WebKit 生效。
3. **服务端数据源接口**
   - `ApiClient` 直连 `/api/crypto/masked/raw`、`/api/crypto/decrypt`、`/api/crypto/envelope/verify` 等接口。
4. **页面底部「操作结果」日志区（`.result-box .log-line`）**
   - 业务失败码 HTTP 仍为 200，且提示由自动消失的 `ElMessage` 承载，因此 UI 层统一轮询累积型日志区。

## 二、核心业务口径与状态机

### 1. 金融金额与结算一致性（`I-17` / `I-18`）
- **精度与容差**：严禁 `float` 直接相等比较；全部使用 `Decimal` + `0.005`（半分钱）容差。
- **单位换算**：数据库 `settle_detail.amount_cents` / `settle_bill.total_amount_cents` / `fund_account.*_cents` 均以**整数分**落库，页面按「元 + 千分位 + `¥`」展示，负数以括号 `(¥3,400.00)` 呈现。
- **NULL 语义**：未清算明细在库中为 `NULL`、页面为 `—`，脚本解析为 `None`（与 `¥0.00` 严格区分），求和时按 0 计。
- **汇总漂移状态机**：
  1. 初始态：存在 `settle_bill.total_amount_cents != SUM(settle_detail.amount_cents)` 的漂移单；
  2. 调整明细金额后：明细表异步写库（约 `0.6s` 延迟），**不回写**结算单汇总字段，页面汇总金额不变；
  3. 点击「重算汇总」后：仅回写该结算单汇总字段，页面汇总合计变化量严格等于调整增量 `delta`；
  4. 模拟清算入账后：直接写库不刷新页面（制造陈旧读数），点击「刷新数据」后快照与账户余额重新对齐；
  5. **测试自洁**：`I-18` 验收前后均调用 `/api/dbconsistency/reset` 复位数据。

### 2. 数据加密与脱敏（`E-01 ~ E-04`）
- **E-01 传输加密（RSA-OAEP）**：公钥异步签发（`0.3~0.8s`），需等指纹与「密钥已就绪」双就绪；OAEP 随机填充使同明文每次密文不同，**禁止密文相等断言**；后端关闭明文回显（`CRYPTO_ECHO_PLAINTEXT=False`），必须反向断言响应不含 `revealedPassword`。
- **E-02 脱敏展示**：个别行 DOM 带 `data-raw` 明文属脏路径，主断言一律以 `/api/crypto/masked/raw` 为准；明文抽屉限时 5 秒自动收起，同条记录冷却期内重复查看返回 `1002`。
- **E-03 密文存储（AES-256-GCM + 多密钥版本）**：库中字段必须为密文（长度 `>= 24` 且非纯数字）+ 随机 IV + HMAC 摘要列；`K0`（已吊销）页面展示「解密失败」，`NULL`（未登记）页面展示「—」且解密接口返回 `2003`；同明文二次登记密文与 IV 均不同，HMAC 摘要列相同。
- **E-04 报文加密与验签**：**解密成功 ≠ 校验通过**。过期时间戳（`2001`）与签名篡改（`2002`）仍可解密出 5 条成交明细，必须分别断言验签失败码。

### 3. UI 菜单与标签一致性规则
- 左侧 6 大分类标题（`.group-title`）、右侧边缘标签（`.edge-tab`，视口宽度 `> 1320px` 可见）、右上角胶囊标签（`.group-tag`）三处文本必须 100% 一致；
- 切换分类时，左侧激活菜单项（`.item.active`）、右侧 `.edge-tab`、右上角 `.group-tag` 背景色须同步切换为对应 `--tab1`~`--tab6` 独立色值，前景色统一 `#1a1a1a`。

## 三、业务异常码字典（HTTP 恒为 200）

| 业务码 `code` | 含义 | 所属场景 | 验收要求 |
| :---: | --- | --- | --- |
| `0` | 成功 | 全局 | 正常流程断言 |
| `1001` | 明文通道被拒 | `E-01` | 断言被拒且页面摘要区被清空 |
| `1002` | 明文查看冷却限流 | `E-02` | 同记录 5s 冷却期内复点触发 |
| `1003` | RSA 密钥轮换后旧密文失效 | `E-01` | 轮换后提交必失败，重签公钥后成功 |
| `2001` | 报文时间戳超出 `±120s` 窗口 | `E-04` | 仍可解密，验签必返 `2001` |
| `2002` | 报文 HMAC 签名被篡改 | `E-04` | 仍可解密，验签必返 `2002` |
| `2003` | 字段未登记或密钥版本不匹配 | `E-03` | 区分 `NULL` 与历史版本未显式指定 |

## 四、不可触碰的验收红线与已知缺陷

1. **禁止绕过安全/校验机制**：`X-01` 只使用万能码 `1234`（不接 OCR）；`X-02` / `C-02` 禁止注入反自动化参数；`M-04` 保留真实弹窗策略。
2. **禁止替被测系统掩盖缺陷**：当前被测后端 `POST /api/seed/new` 在旧进程未重启时稳定返回 `HTTP 500`（影响 `X-04`）。验收脚本必须**如实上报为被测后端缺陷**，不得 skip 或修改断言强行通过。
3. **禁止破坏环境数据**：凡写库场景（`I-18` / `E-03`）验收前后必须 reset 复位。
